    A student asked an AI assistant: "Remove the outliers from the benzene data and give me the mean." It returned this, and it runs without an error.

    import pandas as pddf = pd.read_csv("benzene_sensor.csv", parse_dates=["datetime"])z = (df["C6H6_ugm3"] - df["C6H6_ugm3"].mean()) / df["C6H6_ugm3"].std()df = df[z.abs() < 3]                 # remove outliersprint(len(df), df["C6H6_ugm3"].mean())

    What can go wrong with this code on your file, and how would you notice?

    Compare with the explanation

    Three things. First, the rule asks only "is this hour far from the two-week mean?" Benzene follows traffic, so real rush-hour peaks are far from the mean and get deleted, while a fault in the middle of the normal daily range is kept. A drop to 0.1 at noon is not unusual for the whole record, only for that hour.

    Second, it deletes whole rows, so the time series now has gaps (Lab 02), and the sensor reading at those hours is thrown away too. Third, the faults themselves inflate the standard deviation, which makes the rule less sensitive.

    You notice by printing which hours were removed and looking at them on the plot next to the second sensor: if the sensor rose at the same hour, the event was real.

    med = df["C6H6_ugm3"].rolling(7, center=True).median() # compare with nearby hours df["suspect"] = (df["C6H6_ugm3"] - med).abs() > 5 # flag, do not delete; then check the sensor

      Check your understanding

      Write first, then compare.

      Why did comparing with the second sensor separate faults from real events better than the other two rules?

      Compare with the explanation

      The other rules look only at benzene, so they can ask only whether a value is unusual. A real rush hour is unusual too. The second sensor answers a different question: did something physical happen at that hour? Traffic raises both instruments; a loose wire changes one. Plants use the same idea with redundant transmitters, mass balances and lab samples. The rule fails if both instruments share the fault, for example a power dip that hits both.

      A trailing 12-hour mean shows the morning peak several hours late and much lower. When is that acceptable, and when is it not?

      Compare with the explanation

      A trailing mean uses only past hours, so it is what a live display can compute, and it always lags by about half the window. It is acceptable for showing a slow trend over weeks, if the chart says it is a 12-hour mean. It is not acceptable for timing an event, judging a peak against a limit, or comparing with another tag. For a report written afterwards, a centered window removes most of the lag; neither keeps the peak height.
