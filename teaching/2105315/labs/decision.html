Check the AI's code

The analyst asked an AI assistant: "Merge the two files, calibrate the sensor on week 1 and count the alert hours." The first lines:

s = pd.read_csv("sensor.csv", parse_dates=["datetime_local"]).rename(columns={"datetime_local": "t"})a = pd.read_csv("analyzer.csv", parse_dates=["datetime_utc"]).rename(columns={"datetime_utc": "t"})df = s.merge(a, on="t").replace(-200, np.nan).dropna()week1 = df[df.t < df.t.min() + pd.Timedelta(days=7)]slope, icept = np.polyfit(week1.PT08_S1_CO, week1.C6H6_ugm3, 1)

The code runs without an error. Name two problems in the first three lines, and what each does to the calibration.

Compare with the explanation

First, the files use different clocks. Renaming both columns to "t" hides it: the merge pairs each sensor hour with the analyzer hour two hours later. Benzene peaks at rush hour, so a two-hour offset pairs high sensor readings with falling benzene. The fit flattens (the slope is about half) and the calibrated sensor underestimates the peaks.

Second, the sensor file repeats three rows. The merge copies the matching analyzer rows, so those hours count twice in the fit. Here the effect is small, but an audit would have found it in one line.

s = s.drop_duplicates() a["t"] = a["t"] + pd.Timedelta(hours=2) # UTC to local summer time; check with a lag scan (Step 6)

08

Defend your decision

Write first, then compare.

Why does a two-hour offset make the fitted slope smaller, rather than just moving the predictions two hours?

Compare with the explanation

The fit pairs each sensor reading with the analyzer value two hours later. At 08:00 the sensor is high, but the paired benzene is the 10:00 value, which has already fallen. High sensor readings are matched with middling benzene and low readings with rising benzene, so the cloud of points is flatter and more scattered: r drops from about 0.9 to about 0.5 and the slope to about half. With half the slope, a rush-hour peak is predicted at about two thirds of its height, and the alert misses many of them. A misaligned calibration is not late; it is wrong.

Write the decision for the site manager in four sentences: the decision, the evidence with numbers, what you did to the raw files, and one limit of the test.

Compare with the explanation

For Demo A: "The sensor may run the hourly alert. Calibrated on 5 to 11 September 2004, it flagged 146 of the 161 hours above 15 µg/m³ in the next three weeks (91 %), with 35 false alarms. The analyzer file was stamped in UTC; we added two hours after a lag scan (r 0.93 against 0.54 for the plain merge) and removed three repeated sensor rows. The test covers three autumn weeks only; the sensor drifts (Lab 05), so it should be checked against the analyzer every month." For Demo B the same steps give 68 %, so the answer is no.
